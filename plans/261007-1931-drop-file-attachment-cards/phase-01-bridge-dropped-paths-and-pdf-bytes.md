# Phase 1 — Bridge: dropped paths and PDF bytes

## Context

The Tauri shell disables Tauri's native drag-drop handler
(`src-tauri/src/webview.rs`, `BuilderCall::DisableDragDropHandler`) so HTML5 DnD
keeps working for tab reorder (`TabBar.tsx`) and pane split
(`SplitWorkspace.tsx`). A dropped file then reaches the page as an HTML5 drop with
no path on the `File` object; today WebKitGTK's default action inserts the file
URI into the textarea. Electron's `File` has no `path` since Electron 32; the
supported route is `webUtils.getPathForFile` in the preload.

PDF thumbnails need the file's bytes in the renderer. `fs:read` is workspace
confined; `fs:read-image` already allows absolute paths because the bytes stay in
a local `<img>`. A PDF read follows the same rationale with a PDF sniff.

## Files

Modify: `src/shared/ipc-types.ts`, `src/shared/bridge/create-omp-api.ts` (+ test),
`src/preload/index.ts`, `src/main/ipc.ts` (+ test if a handler test file exists),
`src-tauri/src/services/ipc.rs`, `src-tauri/src/services/mod.rs`, API snapshot
files regenerated by `scripts/check-module.sh`.
Create: `src/renderer/lib/dropped-files.ts`, `src/renderer/lib/dropped-files.test.ts`.

## Steps

1. **Spike first (30 min).** On the virtual display
   (`scripts/virtual-display.sh run -- bun run dev:tauri -- --user-data-dir=$(mktemp -d)`)
   add a temporary `drop` listener that logs `event.dataTransfer.types` and
   `getData("text/uri-list")`, drop a file with `scripts/virtual-display.sh xdotool`
   or a manual drag in the viewer, and confirm file URIs arrive. Remove the
   listener. If they do not arrive on Wayland or X11, stop and report: the
   fallback is to enable Tauri's handler for the main window only and route
   `DragDropEvent::Drop { paths, position }` to the renderer as an event, which
   needs a decision because it disables HTML5 DnD in that window.
2. `dropped-files.ts`:
   - `isFileDrag(data)`: `data?.types` includes `"Files"`.
   - `droppedFilePaths(data)`: parse `text/uri-list` (skip `#` comment lines),
     keep `file://` URIs, decode with `decodeURIComponent` on the pathname
     (`new URL(uri).pathname`), drop non-absolute results. If none came from the
     URI list, map `data.files` through `window.omp.system.pathForFile` when it
     exists and drop empty strings. De-duplicate, keep drop order.
3. Bridge `system.pathForFile`: in `src/preload/index.ts`, import `webUtils` and
   pass `pathForFile: file => webUtils.getPathForFile(file)` into `createOmpApi`
   through a new optional argument, so `create-omp-api.ts` stays shell-neutral and
   the Tauri bridge leaves it `undefined`. Add the optional member to the
   `system` type in `ipc-types.ts`.
4. `fs:read-pdf` (`IPC_COMMANDS.FS_READ_PDF`), payload `{ path }`, result
   `IpcFsReadPdfResult` (see plan.md). Absolute or `~` paths only; must be a
   regular file; size cap 32 MB; first five bytes must be `%PDF-`; returns base64.
   Never throws — errors come back as `ok: false`.
   - Electron: handler in `src/main/ipc.ts` beside `FS_READ_IMAGE`.
   - Tauri: `fs_read_pdf` in `services/ipc.rs` beside `fs_read_image` (reuse its
     `expand_home`), registered in `services/mod.rs` with `Scope::Main` in both
     the scope table and `reg.register`.
   - Bridge: `fs.readPdf(path)` in `create-omp-api.ts`.
5. Rust unit tests for `fs_read_pdf` (non-PDF rejected, over-cap rejected,
   relative path rejected, good PDF returns base64) with matching TS tests for the
   Electron handler so `scripts/check-test-parity.ts` stays green.
6. Regenerate API snapshots: `bash scripts/check-module.sh snapshots`.

## Validation

- `bunx vitest run src/renderer/lib/dropped-files.test.ts src/shared/bridge`
  (uri-list with spaces `%20`, Unicode names, comment lines, non-file URIs, the
  `pathForFile` fallback, duplicates).
- clippy, `cargo test`, test parity and snapshots per plan.md.

## Risks and rollback

- URI list missing on some compositors: see step 1 fallback.
- Rollback: revert the phase's commit; nothing else calls the new members until
  phase 4.

## Implementation notes (2026-10-07)

- First spike (Tauri dev, Xvfb X11, WebKitGTK 2.52.6, GTK3 drag source with two
  files): the page's `drop` saw `types = ["text/uri-list", "text/html"]`, no
  `Files`, and an empty `getData("text/uri-list")`. WebKit hides dropped file
  paths from the page.
- Resolution, with Tauri's drop handler still disabled: `webview.rs` connects
  only a `drag-data-received` observer on Linux main windows (no `drag-drop`
  handler, no `drop_finish`). For the `text/uri-list` target it emits
  `system:native-drop-paths` `{ paths }` (local, decoded, absolute, deduplicated;
  an empty list clears paths left by an abandoned drag). The Tauri bridge exposes
  `system.onNativeDropPaths`; `dropped-files.ts` adds `resolveDroppedPaths`, and
  `isFileDrag` also accepts `text/uri-list`.
- Re-run spike: the renderer got both paths of a two-file drop; the page's
  `drop` fired on the composer textarea and `resolveDroppedPaths` returned both
  paths. The paths arrive once at drag enter and WebKitGTK sends no `dragover`
  while the pointer rests, so they stay valid for 10 s after the last file-drag
  event (2 s missed a 2.5 s pause). Tab reorder could not be exercised: the
  stale local sidecar blocks a second tab. An in-page tab-chip drag still fired
  `dragstart`/`dragend`.
- The Electron PDF read lives in `src/main/fs-read-pdf.ts` (mirrored in
  `services/ipc.rs` via `contracts/services.parity.json`); `channels.rs` counts
  92 channels; `ports.api.txt` and `services.api.txt` list `fs_read_pdf`.
