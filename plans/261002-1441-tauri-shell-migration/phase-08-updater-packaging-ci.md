# Phase 8: Updater, packaging and CI (module `updater`)

## Goal

The Tauri build installs, updates and is released the way the Electron build is, with the same product identity and profile. The updater reads `latest-linux.yml` (and, from Phase 12, `latest-mac.yml`/`latest.yml`) from the publishing repo recorded in the Validation Log (`tung491/oh-my-pi-gui`). The release assets keep their current names, and CI builds and tests the Rust core. The first cutover is Linux only (Validation Log). The macOS and Windows configs are written and invariant-tested here, but built and verified in Phase 12.

## Decision this phase implements

Port `src/main/updater.ts` + `updater-state.ts` to Rust and keep the yml feeds. The user confirmed this on 2026-10-02 (`plan.md` → Validation Log). Do not add `tauri-plugin-updater`. Reasons: after Phase 1, the installed Electron builds read these feeds from the publishing repo, so the cutover needs no separate handover feed; the trust model stays as it is today (HTTPS from GitHub plus a sha512 from the feed); and no signing keys need managing. If the Validation Log records the other option (Tauri updater with `latest.json` and minisign), stop and ask for a revised phase file.

### Task 8.2: Feeds, download and install
- Goal: `updater:check|download|apply|getStatus|version` and the `updater:status` replay stream behave like `updater.ts`.
- Target: `src-tauri/src/updater/{feed,install,mod,ipc}.rs`.
- Steps:
  1. Feed: fetch `https://github.com/<publishing repo>/releases/latest/download/latest-linux.yml` (macOS `latest-mac.yml`, Windows `latest.yml`), where the publishing repo is the Validation Log's (`tung491/oh-my-pi-gui`). Keep it in one constant shared with the download base, read as `option_env!("SAI_ATLAS_UPDATE_BASE").unwrap_or(<the GitHub base>)`: a build-time override only, so Phase 10 Task 10.5 step 5 can build a test bundle that reads a local feed, with no runtime switch in shipped builds (Task 8.4 asserts that no `package:*` or release script sets it). Parse with `serde_yml`, compare against `ctx.host.app_version()` with `semver`, and honor `minimumSystemVersion` on macOS (skip an update the OS cannot run). Checks are off in dev (`tauri::is_dev()`) unless `OMP_DEV_UPDATE_CHECK=1`, as `updater.ts:236` does. Check every 4 h from a timer started in `updater::init`. Publish each status change with `ctx.bridge.broadcast_main("updater:status", status)`; `updater:getStatus` answers `UpdaterPort::status()`. `UpdaterPort::check_now(&self)` (the menu's "Check for Updates…", called by `desktop`) runs the same check through `self.ctx()`.
  2. Download: user-initiated, `RELEASE_DOWNLOAD_BASE`, `.partial` resume with `Range`, sha512 verification against the feed, progress every 100 ms through `ctx.bridge.broadcast_main("updater:status", …)`.
  3. Install by package kind (`linux_package_kind` from `APPIMAGE`/`APPDIR` and the executable path). Every OS action goes through `ctx.host` (`Host` in `ports.rs:762-787`); this module never calls a Tauri plugin directly.
     - macOS: the same manual flow as today, `openManualInstaller` (`updater.ts:119-123`): `ctx.host.reveal_in_folder(path)`, then `ctx.host.open_path(path)`; on error report `MainTextKey::UpdatesOpenInstallerFailed` (`updates.openInstallerFailed`).
     - Linux AppImage: after `ctx.desktop.approve_quit_before_install().await` returns `true`, replace the file at `$APPIMAGE` atomically (write next to it, `rename`), keep the executable bit, then `ctx.host.relaunch_after_exit(PathBuf::from(<$APPIMAGE>))` and `ctx.host.exit(0)`. The relaunch takes no arguments (`updater.ts:365-367`: a launch link or workspace must not be replayed). `lib.rs` starts the program in the `RunEvent::Exit` arm, after the frozen shutdown order and after the single-instance D-Bus name is released (`lib.rs:236-247, 439-444`). It inherits this process's environment minus `APPIMAGE_EXIT_AFTER_INSTALL`, so `APPDIR`, `APPIMAGE` and `LD_LIBRARY_PATH` still name the old mount until the new AppImage's `AppRun` resets them; Phase 10 Task 10.5 verifies that on a real self-update. `ctx.host.exit(0)` arrives at desktop as `on_exit_requested(Some(0))`, which never vetoes (Phase 5 Task 5.8).
     - Linux deb: read electron-updater's `DebUpdater` (`node_modules/electron-updater/out/DebUpdater.js`) and port its command sequence, including any dependency-fix fallback, as argv vectors, never through a shell. Re-verify the sha512 immediately before the privileged call. Call `pkexec /usr/bin/dpkg -i -- <absolute path>` by absolute paths (a privileged child, spawned with `tokio::process`). After approval and a successful install, `ctx.host.relaunch_after_exit(PathBuf::from("/usr/bin/sai-atlas"))`, then `ctx.host.exit(0)`. On failure, `ctx.desktop.withdraw_quit_approval()` and report `MainTextKey::UpdatesInstallFailed` (`updates.installFailed`). Document the remaining same-user TOCTOU window exactly as README.md already does for Electron (README → Linux), and write unit tests for the command builder: `uses absolute dpkg path`, `passes the package after --`, `never builds a shell string`.
     - Windows: start the downloaded NSIS installer, then `ctx.host.exit(0)`.
     - Install on quit: when `installs_on_quit(mode, kind)` holds (automatic AppImage, macOS, Windows), `UpdaterPort::shutdown(&self)` performs the install. The frozen shutdown order runs it after every sidecar has stopped and before `desktop.shutdown` (`lib.rs:299-306`). Its future runs inside `block_on` on the main thread, so it must not wait on anything that needs the main thread.
     - Tests use `testing::fake_ctx_cyclic` with the real `Updater` installed; assert on `FakeHost::relaunches`, `FakeHost::exit_codes`, `FakeDesktop::approve_install` and `fakes.desktop.log`.
  4. Version: `updater:version` returns `ctx.host.app_version()`. `TauriHost` answers `package_info().version`, which `tauri.conf.json` → `"version": "../package.json"` ties to `package.json`.
- Verify: `cargo test --manifest-path src-tauri/Cargo.toml updater::` exits 0, and `grep -c "IpcError::not_ported" src-tauri/src/updater/ipc.rs` prints `0` (the file's header comment mentions `not_ported` by name, so grep for the call).

### Task 8.3: Bundle configuration
- Goal: `cargo tauri build` produces correctly named, correctly identified packages on Linux, with the macOS and Windows configs written and validated by tests.
- Steps:
  1. `tauri.conf.json` already carries the Phase 2 values (`productName`, `identifier`, `mainBinaryName: "sai-atlas"`, `"version": "../package.json"`, `build.*`, `app.windows: []`, `enableGTKAppId`, `withGlobalTauri: false`, the CSP with `dangerousDisableAssetCspModification: ["style-src"]`, and the `omp` scheme under `plugins.deep-link.desktop.schemes`); keep them. Change `bundle.active` to `true`, and add `bundle.icon` (generated in step 4), `bundle.category: "DeveloperTool"` and `plugins.deep-link.mobile: []`. Sidecar placement is per OS, because `paths::resolve_bundled_omp()` looks next to the executable and the deb installs the executable at `/usr/bin/sai-atlas`: `bundle.externalBin: ["binaries/omp"]` would install the sidecar as `/usr/bin/omp`, which puts a GUI-pinned `omp` on every user's `PATH` and makes `dpkg -i` fail when another package owns that path. So `externalBin: ["binaries/omp"]` goes only into `tauri.macos.conf.json` (it lands in `Contents/MacOS/` beside the executable) and `tauri.windows.conf.json` (beside `sai-atlas.exe`). On Linux (step 3), the sidecar ships as a resource instead.
  2. `tauri.macos.conf.json` (built in Phase 12): `bundle.targets: ["dmg", "app"]`, `bundle.macOS.minimumSystemVersion: "13.3"` (Safari 16.4 WebKit; revisit in Phase 12), `signingIdentity: "-"`, `entitlements: "macos/app.entitlements"`. `macos/app.entitlements` grants only `com.apple.security.device.audio-input`; the dyld, library-validation, JIT and unsigned-memory exemptions in `resources/entitlements.mac.plist` were for Electron. The Bun-compiled `omp` needs JIT, so write `macos/omp.entitlements` with `allow-jit` and `allow-unsigned-executable-memory` only, applied to the sidecar when it is signed (Phase 12 verifies how).   3. `tauri.linux.conf.json`: `bundle.targets: ["appimage", "deb"]`. Sidecar: no `externalBin`; `bundle.resources: { "binaries/omp-x86_64-unknown-linux-gnu": "omp" }`. The last two are required, not optional: the web-process sandbox is always on (Phase 2), WebKit treats a missing `bwrap` as fatal once it is, and the spike's .deb listed only `libayatana-appindicator3-1, libwebkit2gtk-4.1-0, libgtk-3-0` (Phase 0 S12). Add a compat symlink `/opt/Sai ATLAS/sai-atlas` → `/usr/bin/sai-atlas` through `deb.files`, because the Electron deb updater relaunches its old `process.execPath` after `dpkg -i` (`src/main/updater.ts:368`). Add `Replaces`/`Conflicts`/`Provides` entries for any older package name the Validation Log lists.
