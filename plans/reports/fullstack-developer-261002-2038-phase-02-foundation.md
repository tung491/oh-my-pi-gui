3. `src-tauri/icons/icon.png` (a copy of `resources/icon.png`) exists because `tauri::generate_context!` requires a PNG window icon on Unix even with `bundle.active: false` (tauri-codegen `find_icon(…, "icons/icon.png")`). Phase 8 regenerates the full icon set with `bunx tauri icon`; the file is in `src-tauri/icons/**`, which Phase 8 owns.

Single-instance id: the plugin derives its D-Bus name from `app.config().identifier`, so for a non-default profile `lib.rs` also sets `context.config_mut().identifier = paths::single_instance_id()` (the app id plus 16 hex chars of the profile path's SHA-256). ## Task 2.9b: contract review

A `code-reviewer` subagent walked every step of Phases 3 to 9 against `ports.rs`, `webview.rs`, `bridge.rs`, `ctx.rs`, `testing.rs`, the foundation helpers and the inventory, and wrote `/home/tung491/WORK/oh-my-pi-gui/plans/261002-1441-tauri-shell-migration/reports/phase-02-contract-review.md`. First pass (at `bc859d4`): 16 GAP rows, two roots.

- Root A: ports were built with `X::new()` and stored as `Arc<dyn XPort>`, so a trait method called by another module (`TabsPort::acquire`, `OmpPort::spawn_env`, `ServicesPort::execute_host_tool`, `UpdaterPort::check_now`) had no route to `AppCtx`. Fix: every constructor takes `ctx: CtxRef` (`Weak<AppCtx>`), `lib.rs::build_ctx` uses `Arc::new_cyclic`, `Desktop::new(app, ctx)`; `testing::fake_ctx_cyclic(&fakes, registry, |ctx, ports| …)` with `testing::Ports` lets a module test install its real port next to the fakes.
- Root B: handlers are `fn` pointers and could not reach their module's state. Fix: `fn as_any(&self) -> &dyn Any` on all six port traits (`ctx.omp.as_any().downcast_ref::<Omp>()`), fakes return `self`.
- Specific: `SidecarHandle::request/kill/dispose` and `TabsPort::command_for_idle_session` return `'static` futures ("queued on stdin before this returns", so `rpc:command` keeps stdin order); `DesktopPort::on_exit_requested(code) -> bool` (`lib.rs` calls `api.prevent_exit()` when true) and `on_reopen` (macOS `RunEvent::Reopen`); `UpdaterPort::shutdown` (install on quit) and `ctx.ollama.shutdown()` added to the shutdown order (now 7 steps: mark_quitting → tabs.dispose_all → omp.shutdown → services.shutdown → ollama.shutdown → updater.shutdown → desktop.shutdown); `Host::relaunch_after_exit(program)` spawned in the `RunEvent::Exit` arm after the single-instance name is released; `MenuCheckForUpdates` as a documented Rust-only i18n key (the Electron menu has no such item); `SidecarOptions.extra_flags` documented as "the manager re-reads `launchProfiles.<cwd>` on every spawn/restart"; `EventBatcher` documented as manager-side (the pool forwards `SidecarEvent::Events` unchanged).
- The reviewer also caught a real defect outside the count: `omp_attach` was a synchronous command and so ran on the main thread, where the `tokio::spawn` calls during attach-time replay would panic. `omp_attach` is now async and `bridge.rs` spawns through a helper that uses the current runtime when there is one (test runtimes with paused time) and Tauri's otherwise.
